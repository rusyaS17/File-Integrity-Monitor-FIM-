# Зерттеу жұмысы: File Integrity Monitor

## 1. Тақырып

**Java негізінде файлдардың тұтастығын бақылау жүйесін әзірлеу (File Integrity Monitor).**

## 2. Өзектілігі

Ақпараттық жүйелерде конфигурациялық файлдар, қолданба файлдары және пайдаланушы деректері рұқсатсыз немесе кездейсоқ өзгеруі мүмкін. Мұндай өзгерістер бағдарламаның жұмысына әсер етуі, деректердің бұзылуына немесе қауіпсіздік оқиғасының белгісі болуына ықпал етеді. File Integrity Monitoring (FIM) файлдардың бастапқы күйін тіркеп, кейінгі өзгерістерді анықтауға көмектеседі.

Wazuh құжаттамасында FIM файлдардың жасалуын, өзгертілуін және жойылуын бақылап, checksum мәндерін baseline-пен салыстыратыны сипатталған [1]. Демек, шағын әрі түсінікті FIM жүйесін әзірлеу файлдық жүйе оқиғаларын өңдеу, криптографиялық хэштеу, деректерді сақтау және бағдарламалық архитектураны практикада меңгеруге мүмкіндік береді.

## 3. Мақсаты

Java бағдарламалау тілі негізінде таңдалған каталогтағы файлдардың тұтастығын бақылап, файлдың қосылуы, өзгертілуі немесе жойылуы туралы ақпаратты тіркейтін қолданба әзірлеу.

## 4. Міндеттері

1. FIM ұғымын және оның ақпараттық қауіпсіздіктегі рөлін зерттеу.
2. Wazuh және OSSEC сияқты қолданыстағы шешімдердің мүмкіндіктерін салыстыру.
3. Файл мазмұнының өзгерісін хэш арқылы анықтау принципін қарастыру.
4. Java NIO WatchService механизмін зерттеу.
5. SHA-256 алгоритмін және Java MessageDigest API қолдануды қарастыру.
6. Файлдардың бастапқы күйі мен оқиғаларын сақтау үшін SQLite дерекқорын жобалау.
7. Core, Application, Persistence және Presentation қабаттарына негізделген архитектура әзірлеу.
8. Console және JavaFX интерфейстерін ортақ бизнес-логикаға қосу.
9. Бағдарламаны автоматты тестілер арқылы тексеру.

## 5. FIM жүйесінің жұмыс принципі

FIM жүйесі әдетте файлдардың бастапқы күйін (baseline) тіркейді. Әр файл үшін SHA-256 сияқты хэш және қажет болған жағдайда файл өлшемі, жолы, тексерілген уақыты секілді атрибуттар сақталады. Кейін файл қайта тексерілгенде жаңа хэш бұрынғы мәнмен салыстырылады. Мәндер сәйкес келмесе, файл мазмұны өзгерген болуы мүмкін.

Негізгі оқиға түрлері:

- **NEW** — бақылау барысында жаңа файл анықталды.
- **MODIFIED** — файл бұрын тіркелген, бірақ хэш мәні өзгерген.
- **DELETED** — бұрын тіркелген файл енді табылмайды.
- **UNCHANGED** — файлдың тексерілген мазмұны baseline-пен сәйкес келеді.
- **ERROR** — файлға қол жеткізу немесе хэштеу кезінде қате пайда болды.

Оқиға түрін анықтау алгоритмі файлдың ағымдағы күйі мен baseline жазбасын салыстыруға негізделеді. Қате болған жағдайда оны өзгертілді немесе жойылды деп қате белгілемеу керек.

## 6. Қолданыстағы шешімдерге шолу

### 6.1 Wazuh

Wazuh — қауіпсіздік мониторингіне арналған ашық бастапқы кодты платформа. Оның FIM модулі файлдар мен каталогтарды бақылайды, бастапқы checksum және атрибуттарды сақтайды, өзгерістерді baseline-пен салыстырады. Құжаттамада жоспарлы сканерлеу және нақты уақыттағы бақылау режимдері көрсетілген [1][2]. Wazuh FIM агент жағында SQLite негізіндегі жергілікті дерекқор қолданатынын да сипаттайды [1].

### 6.2 OSSEC

OSSEC Syscheck компоненті файлдардың тұтастығын MD5, SHA-1 және SHA-256 checksum мәндері арқылы тексере алады. Ресми құжаттамада жоспарлы тексерулер және Linux/Windows жүйелеріндегі real-time бақылау мүмкіндігі сипатталған. Сонымен қатар real-time режимінің шектеулері бар: кейбір атрибуттар жоспарлы сканерлеу кезінде ғана анықталуы мүмкін [3].

### 6.3 Салыстыру

| Критерий | Wazuh FIM | OSSEC Syscheck | Осы жобаның мақсаты |
|---|---|---|---|
| Бастапқы күй (baseline) | Бар | Бар | Қарастырылған |
| Хэш арқылы салыстыру | Бар | Бар | SHA-256 |
| Жоспарлы тексеру | Бар | Бар | Қайта сканерлеу жоспарланады |
| Оқиғаға негізделген бақылау | Бар | Қолдау бар | Java WatchService |
| Оқиғалар тарихы | Агент/сервер инфрақұрылымы | Агент/менеджер архитектурасы | Жергілікті SQLite |
| Интерфейс | Веб-басқару және платформа | Негізінен агент/менеджер | Console + JavaFX |
| Негізгі бағыт | Кәсіптік қауіпсіздік мониторингі | Хост негізіндегі қауіпсіздік | Оқу және демонстрациялық FIM |

Бұл кесте өнімдердің толық функционалдық теңдігін білдірмейді. Салыстыру тек осы жобаның міндеттеріне қатысты негізгі қағидаларды көрсетеді.

## 7. Таңдалған технологияларды негіздеу

### 7.1 Java

Java объектіге бағытталған бағдарламалау, стандартты кітапханалар және кросс-платформалық іске қосу мүмкіндіктерін ұсынады. Жобаның негізгі логикасы Java тілінде жазылады.

### 7.2 Java NIO WatchService

WatchService каталогтардағы файлдық жүйе оқиғаларын қабылдауға арналған Java API. Ол ENTRY_CREATE, ENTRY_MODIFY және ENTRY_DELETE оқиғаларын жеткізе алады [4]. Бұл механизм файлдың мазмұнын өзі тексермейді; оқиға келгеннен кейін бағдарлама файлды қайта оқып, хэшін есептеуі керек.

WatchService оқиғалары операциялық жүйе мен файлдық жүйеге тәуелді. Оқиғалар біріктірілуі немесе жоғалуы мүмкін, сондықтан тек watcher-ге сүйену толық кепілдік бермейді. Осы себепті жобада оқиғаларды өңдеу және мерзімді толық сканерлеу тәсілдері бірге қарастырылады.

### 7.3 SHA-256 және MessageDigest

SHA-256 — бір бағытты криптографиялық хэш функциясы. Бірдей кіріс деректері бірдей хэш береді; файл мазмұны өзгерсе, хэштің өзгеруі күтіледі. Java-да хэш есептеу үшін MessageDigest API қолданылады [5].

Хэштеу шифрлау емес: хэштен бастапқы файл мазмұнын қалпына келтіру көзделмейді. Сондай-ақ SHA-256 baseline-нің сенімділігін өздігінен қамтамасыз етпейді. Егер шабуылдаушы файлмен бірге baseline-ді де өзгерте алса, салыстыру нәтижесі сенімсіз болуы мүмкін.

### 7.4 SQLite

SQLite — қолданба ішінде пайдалануға болатын ықшам реляциялық дерекқор. Ол жеке сервер процесін талап етпейді және файл түрінде сақталады [6]. Жоба файлдардың baseline жазбаларын және анықталған оқиғаларды жергілікті сақтау үшін SQLite қолдануды жоспарлайды.

### 7.5 JavaFX және JUnit

JavaFX desktop интерфейсін құруға, ал JUnit 5 автоматты тестілер жазуға арналған. Бұл технологиялар негізгі логика мен интерфейсті бөлек дамытуға мүмкіндік береді.

## 8. Жүйенің ұсынылатын жұмыс алгоритмі

1. Пайдаланушы каталог жолын көрсетеді.
2. Қолданба каталогтың бар-жоғын және қолжетімділігін тексереді.
3. Бастапқы сканерлеу барлық қолжетімді файлдарды табады.
4. Әр файл үшін SHA-256 есептеліп, baseline дерекқорға сақталады.
5. WatchService каталогқа және оның ішкі каталогтарына тіркеледі.
6. Оқиға түскенде бағдарлама файлдың ағымдағы күйін тексереді.
7. Файл бар болса, хэш есептеліп baseline-пен салыстырылады.
8. Файл табылмаса, жою оқиғасы тіркеледі; бірақ қолжетімсіздік пен нақты жою жағдайлары ажыратылуы тиіс.
9. Нәтиже SQLite-қа жазылып, интерфейсте көрсетіледі.
10. Белгілі бір аралықпен толық қайта сканерлеу жүргізіліп, watcher өткізіп алған өзгерістер ізделеді.

## 9. Дерекқордың бастапқы жобасы

### monitored_files

| Өріс | Түрі | Мақсаты |
|---|---|---|
| id | INTEGER PRIMARY KEY | Бірегей жазба |
| file_path | TEXT NOT NULL UNIQUE | Файлдың толық жолы |
| sha256_hash | TEXT | Соңғы baseline хэші |
| file_size | INTEGER | Файл өлшемі |
| last_checked_at | TEXT | Соңғы тексеру уақыты |
| status | TEXT NOT NULL | PRESENT немесе MISSING |

### file_events

| Өріс | Түрі | Мақсаты |
|---|---|---|
| id | INTEGER PRIMARY KEY | Оқиға идентификаторы |
| file_id | INTEGER | monitored_files кестесіне сілтеме |
| file_path | TEXT NOT NULL | Оқиға кезіндегі файл жолы |
| event_type | TEXT NOT NULL | NEW / MODIFIED / DELETED / ERROR |
| old_hash | TEXT | Бұрынғы хэш |
| new_hash | TEXT | Жаңа хэш |
| occurred_at | TEXT NOT NULL | Оқиға уақыты |
| details | TEXT | Қосымша ақпарат |

Соңғы схема іске асыру кезінде нақтылауды қажет етеді: сыртқы кілттер, индекстер, уақыт белгілерінің бірыңғай форматы және baseline жаңарту транзакциялары қарастырылады.

## 10. Күтілетін нәтиже

Жоба нәтижесінде пайдаланушы каталогты таңдап, оның файлдық күйін бастапқы тіркей алатын, файлдардың қосылуын/өзгеруін/жойылуын анықтайтын және оқиғалар тарихын қарайтын бағдарлама әзірленуі тиіс. Жүйеде консольдік және графикалық интерфейс ортақ Core логикасын пайдаланады.

## 11. Қорытынды

Зерттеу FIM жүйесінің негізінде бастапқы күйді сақтау, файл мазмұнын хэштеу және кейінгі нәтижелермен салыстыру қағидалары жатқанын көрсетті. Java NIO WatchService оқиғаға негізделген бақылауға мүмкіндік береді, алайда сенімдірек нәтиже үшін мерзімді қайта сканерлеумен толықтырылуы керек. SHA-256 файл мазмұнының өзгерісін анықтауға жарамды, ал SQLite жергілікті оқиғалар журналын сақтауға қолайлы. Осы технологиялар жобаның оқу мақсаттарына сәйкес келеді.
