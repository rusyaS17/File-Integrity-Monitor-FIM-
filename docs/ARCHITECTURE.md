# Жүйе архитектурасы

## 1. Архитектуралық шешім

Жоба қабатталған архитектура қағидасымен құрылады. Console және JavaFX интерфейстері бірдей Application қызметтерін шақырады. Файлдарды бақылау, хэштеу және оқиғаларды жіктеу логикасы интерфейске тәуелсіз Core модулінде орналасады.

## 2. Қабаттар

### Presentation
- Console UI: командаларды қабылдау және нәтижені мәтін түрінде көрсету.
- Desktop UI: JavaFX терезелері, каталог таңдау және оқиғалар кестесі.

### Application
- MonitoringService: мониторинг сессиясын бастау/тоқтату.
- EventProcessor: файлдық оқиғаны тексеру және домендік оқиғаға айналдыру.
- ScanService: бастапқы және мерзімді сканерлеу сценарийлері.

### Core
- FileWatcher: WatchService оқиғаларын қабылдау.
- FileScanner: каталог мазмұнын сканерлеу.
- HashCalculator: SHA-256 есептеу.
- IntegrityChecker: baseline пен ағымдағы хэшті салыстыру.
- FileEvent: NEW, MODIFIED, DELETED, ERROR домендік оқиғасы.

### Persistence
- DatabaseManager: SQLite байланысын және схеманы басқару.
- FileRepository: файлдардың baseline күйін сақтау.
- EventRepository: оқиғалар тарихын сақтау.

## 3. Негізгі деректер ағыны

1. UI MonitoringService.start(path) шақырады.
2. ScanService каталогты сканерлейді.
3. HashCalculator әр қолжетімді файлдың SHA-256 хэшін есептейді.
4. FileRepository baseline жазбаларын сақтайды.
5. FileWatcher каталогтарды бақылауға тіркейді.
6. WatchService оқиғасы EventProcessor-ге беріледі.
7. EventProcessor файлдың бар-жоғын және ағымдағы хэшін тексереді.
8. IntegrityChecker оқиға түрін анықтайды.
9. EventRepository оқиғаны сақтайды.
10. UI жаңартылған оқиғалар тізімін көрсетеді.

## 4. Маңызды жобалау шешімдері

- **Бизнес-логика интерфейстен тәуелсіз:** Console және Desktop бірдей қызметтерді пайдаланады.
- **Оқиға және нақты күйді ажырату:** WatchService оқиғасы тек қайта тексеруге түрткі болады; ол автоматты түрде MODIFIED дегенді білдірмейді.
- **Қайта сканерлеу:** файлдық оқиғалар жоғалуы немесе біріктірілуі мүмкін болғандықтан, мерзімді reconciliation scan қарастырылады.
- **Қателерді бөлек тіркеу:** файл оқылмаса, оны DELETED деп белгілемеу керек.
- **Baseline қауіпсіздігі:** SQLite файлы мен бастапқы хэштерді қорғау талаптары құжатталады.
- **Транзакциялар:** файл күйі мен оған қатысты оқиға бірізді сақталуы керек.

## 5. Бастапқы пакет құрылымы

```text
com.rustem.fim
├── app
│   ├── MonitoringService
│   ├── ScanService
│   └── EventProcessor
├── core
│   ├── FileScanner
│   ├── FileWatcher
│   ├── HashCalculator
│   ├── IntegrityChecker
│   └── FileEvent
├── persistence
│   ├── DatabaseManager
│   ├── FileRepository
│   └── EventRepository
├── ui
│   ├── console
│   └── desktop
└── Main
```

Бұл — бастапқы жоспар. Maven модульдері мен нақты package атаулары код басталған кезде бекітіледі.

## 6. Қателер мен шеткі жағдайлар

- Файл хэш есептеу кезінде өзгеріп кетуі мүмкін: өлшемі/уақыты қайта тексеріліп, қажет болса хэштеу қайталанады.
- Бір файлға бірнеше WatchService оқиғасы түсуі мүмкін: оқиғаларды қысқа уақытқа біріктіру (debounce) қарастырылады.
- Каталог ішінде жаңа ішкі каталог пайда болса, оған watcher тіркелуі керек.
- Құқық жеткіліксіз болса, ERROR оқиғасы немесе диагностикалық хабар көрсетіледі.
- Қолданба тоқтап қайта қосылғанда baseline дерекқордан қалпына келтіріледі, кейін толық сканерлеумен салыстырылады.
- Символдық сілтемелерге қатысты саясат нақты белгіленуі тиіс (әдепкіде сыртқы каталогтарға өтпеу ұсынылады).
