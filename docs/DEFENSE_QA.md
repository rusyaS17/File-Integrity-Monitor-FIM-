# Қорғауға дайындық

## Жобаның мақсаты
File Integrity Monitor — таңдалған каталогтағы файлдардың тұтастығын SHA-256 хэштері арқылы тексеретін оқу жобасы. Бағдарлама файлдардың бастапқы хэштерін baseline файлына сақтайды және кейінгі сканерлеу кезінде оларды салыстырады.

## Негізгі сұрақтар мен жауаптар

**1. FIM дегеніміз не?**
FIM (File Integrity Monitoring) — файлдардың қосылуын, өзгертілуін немесе жойылуын анықтайтын жүйе.

**2. SHA-256 не үшін керек?**
SHA-256 файл мазмұнынан тұрақты ұзындықтағы хэш есептейді. Файл мазмұны өзгерсе, хэш те әдетте өзгереді. Бұл жоба файлдың тұтастығын салыстыру үшін SHA-256 қолданады.

**3. Baseline дегеніміз не?**
Baseline — файлдардың сенімді бастапқы күйі: файл жолы және сол файлдың SHA-256 хэші. Ол `baseline.txt` ішінде сақталады.

**4. Бағдарлама қайта іске қосылғанда бастапқы хэштер қалай сақталады?**
`loadBaselineFromFile()` baseline файлын оқып, жолдар мен хэштерді Map коллекциясына қайта жүктейді.

**5. SAFE, MODIFIED, NEW және DELETED айырмашылығы қандай?**
SAFE — хэш бірдей; MODIFIED — хэш басқа; NEW — baseline ішінде болмаған файл; DELETED — baseline ішінде болған, бірақ қазір жоқ файл.

**6. Неге сканерлеу кезінде baseline автоматты түрде жаңартылмайды?**
Өйткені өзгерген файлды жаңа бастапқы күй деп қабылдап қоймау керек. Baseline тек пайдаланушы `init` командасын әдейі орындағанда жаңартылады.

**7. SHA-256 шифрлау ма?**
Жоқ. SHA-256 — біржақты хэштеу алгоритмі, шифрлау емес.

**8. Қазір бағдарлама нені істей алмайды?**
Қазіргі нұсқа каталогты тек іске қосылған кезде сканерлейді. Үздіксіз бақылау, дерекқор және графикалық интерфейс әлі қосылмаған.

## Демонстрация сценарийі
1. `mvn clean test` — автоматты тесттерді көрсету.
2. `mvn exec:java -Dexec.args="init"` — бастапқы baseline жасау.
3. `monitored/important-document.txt` мазмұнын өзгерту.
4. `monitored/` ішіне жаңа файл қосу.
5. `monitored/system-config.txt` файлын жою.
6. `mvn exec:java` — есептен MODIFIED, NEW және DELETED мәртебелерін көрсету.
